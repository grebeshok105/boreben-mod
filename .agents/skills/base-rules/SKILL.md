# Base Rules — Vanguard Addon

Жёсткие правила поведения в этом репо. Это **аддон** к основному моду `superheroes` (репо `grebeshok105/grebeshok105`), а не самостоятельный мод. Он подключается к тому же набору механик и к той же creative-вкладке, но кодом живёт отдельно.

## Не делать без явного запроса
- НЕ создавать `.md` файлы (README, CHANGELOG, docs) без запроса
- НЕ комментировать код если не просили
- НЕ делать косметические правки (форматирование, импорты, переименования) — только по делу
- НЕ описывать структуру проекта в комментариях / правилах — она видна через filesystem
- НЕ использовать deprecated API Minecraft / Fabric / Loom
- НЕ копировать классы/механики из основного `superheroes` мода в аддон. Если нужна механика основного мода — это прямой признак что её надо сделать публичной в основном моде, а не дублировать
- НЕ менять идентификаторы / неймспейсы основного мода, не «лезть» в его регистры — только потреблять их через публичное API (см. skill `addon-integration`)

## Зависимость от superheroes mod
- Аддон **зависит** от основного мода. В `fabric.mod.json` это `"depends": { "superheroes": "*", ... }`. См. skill `addon-integration` для деталей.
- Перед коммитом проверяй что `./gradlew compileJava` не падает на отсутствующем `superheroes`. Скорее всего основной мод подключён как `modImplementation` через локальный jar или maven publish.

## Ассеты
- Ассеты класть в `src/main/resources/assets/<addon-mod-id>/...`, а **не** в `superheroes/...`. Иначе аддон затрёт ресурсы основного мода.
- Сырые ассеты (если будут) — в `art-source/` на корне репа.
- Звуки в рантайме — только OGG Vorbis. MP3 от пользователя — `ffmpeg -c:a libvorbis -qscale:a 5`.
- Локализационные ключи всегда оба: `lang/en_us.json` и `lang/ru_ru.json`.

## Стиль коммитов / PR
- Коммиты на английском, conventional-style: `feat(scope): ...`, `fix(scope): ...`
- Branch: `devin/$(date +%s)-<short-name>` (это уже дефолт у Devin)
- PR title в том же формате что коммит
- PR description — на русском (так общается пользователь), детально перечислить изменения и Review Checklist

## Версионирование
- `gradle.properties` `mod_version` — менять только при релизе. В обычных PR не трогать.
- Версии: `0.1.X` пока не стабилизировано, потом `1.0.X`.

## Коммуникация
- Пользователь пишет на русском → отвечать на русском, тех.термины оставлять английскими
- Минимизировать токены — короткие, по делу
- При завершении задачи давать ссылку на PR / релиз, не спамить промежуточные апдейты
